# Java 变量、数据类型与类型转换精讲

> **定位**：只记跨知识点的联系、重点难点与易错点，不重复教程正文；完整讲解与案例见下方教程，题目练习见对应问答。

## 二、技术点之间的联系

- 字面量是"数据的书写格式"，变量是"数据的容器"，数据类型则是"容器的规格"——三者共同回答一个问题：数据在 Java 程序里怎么写、怎么存。
- 数据类型的范围差异是类型转换存在的根本原因：小杯子的水可以倒进大杯子（自动转换），大杯子的水倒进小杯子可能溢出（强制转换可能丢数据）。
- 表达式自动类型提升是自动类型转换在运算场景下的延伸；而扩展赋值运算符（`+=` 等）底层隐含了强制类型转换，把"运算—提升—赋值"三步压缩成一步。
- 字符类型 `char` 之所以能和整数互相转换，是因为字符在计算机底层存的就是编码表（如 ASCII）中的数字：`'A'` 是 65、`'a'` 是 97、`'0'` 是 48。这也是 `int` 与 `char` 混算不报错的原因。
- Scanner 录入的数据进入变量，变量再参与运算和流程控制，构成"输入 → 处理 → 输出"的最小程序闭环。

补充背景：计算机底层用二进制存数据，逢 2 进 1；最小存储单元是字节（1B = 8bit），其上是 KB、MB、GB（均按 1024 进位）。Java 支持直接书写二进制（`0B` 开头）、八进制（`0` 开头）、十六进制（`0X` 开头）的字面量，便于观察二进制。

## 四、重点与难点分析

### 重点 1：默认类型意识

整数字面量默认 `int`、小数字面量默认 `double`。写 `long l = 10000000000;` 会编译报错，因为右侧先按 `int` 解读已越界，必须写 `10000000000L`；写 `float f = 3.14;` 同样报错，必须写 `3.14F`。

### 重点 2：byte 的边界

`byte` 范围只有 -128 ~ 127，是溢出事故的高发区。给它赋字面量 `127` 可以，赋 `128` 直接编译错；把 `int` 强转成 `byte` 时更要预判结果是否还在范围内。

### 难点 1：强制转换的截断逻辑

强转不是"四舍五入"也不是"取模"，而是**二进制位的直接截断**：保留目标类型的低 N 位，高位丢弃，再按补码解释。理解这一点才能解释 `(byte)1500 == -36` 这类结果。工程建议：慎用或者不用强转，先放大容器。

### 难点 2：表达式提升的隐蔽性

`byte + byte` 得 `int`、`char + int` 得 `int` 这类提升在编译期悄然发生。写 `byte b = b1 + b2;` 会报错，新手常困惑"两个 byte 相加为什么不是 byte"。记法：小于 int 的类型参与运算，结果至少是 int。

### 易错点清单

- 字符用单引号且只能一个字符，字符串用双引号，混用报错；
- `23` 是 int，`23L` 是 long；`23.8` 是 double，`23.8F` 是 float；
- 变量未初始化就使用，编译报错；
- `Scanner` 需要 `import java.util.Scanner;`，而 `System`、`String` 在 `java.lang` 包下无需导包。
