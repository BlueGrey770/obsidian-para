# Java 运算符精讲与常见坑

> **定位**：只记跨知识点的联系、重点难点与易错点，不重复教程正文；完整讲解与案例见下方教程，题目练习见对应问答。

## 二、技术点之间的联系

- 算术运算符负责"算出结果"，关系运算符负责"判断真假"，逻辑运算符负责"把多个真假条件组合起来"，三元运算符把"判断 + 二选一取值"压缩成一行——四者层层递进，构成流程控制的表达式基础。
- `/` 和 `%` 是孪生兄弟：一个取商（去掉低位），一个取余（留下低位），数值拆分、奇偶判断、水仙花数等经典题目都靠这对组合。
- 扩展赋值运算符与强制类型转换直接相关：`a += b` 的底层形式是 `a = (a的类型)(a + b)`，自带强转，这是它与 `a = a + b` 的本质差异。
- 自增自减的前后位置问题，本质是"取值时机"问题，它和 Java 表达式从左到右的求值顺序绑定，也是面试和笔试的常见考点。
- 关系运算符产出布尔值，布尔值正好是逻辑运算符、if 分支、三元运算符的输入——这条数据通路决定了"比较必须发生在条件组合之前"。

## 四、重点与难点分析

### 重点 1：`/` 的整数截断

`5 / 2` 结果是 `2` 不是 `2.5`——因为最高类型是整数。想让结果是 2.5，把接收变量改成 `double` 还不够（`double i = 5 / 2;` 依然输出 2.0，因为右侧已经按整数算完），必须让参与运算的数据中有小数：`5 / 2.0`。

### 重点 2：`==` 与 `=` 的书写

判断是否相等一定是 `==`，误写成 `=` 就变成赋值语句。在 if 条件里写错会直接改变程序逻辑甚至编译报错。

### 难点 1：自增自减混合表达式

面对 `int rs = c++ + ++c - --d - ++d + 1 + c--;` 这类题目，方法是从左到右逐项拆解，每遇到一个 `++/--` 就立刻更新该变量的当前值，并区分"取值"发生在自增前还是自增后。笔试爱考、工程禁用——真实代码里一个表达式最多出现一次自增自减。

### 难点 2：`+=` 隐含强转的双刃剑

`a += b` 的隐式强转让代码简洁，但也会悄悄丢精度（如上例中 22.3 被截成 22）。笔试题常拿"为什么 `a += b` 不报错而 `a = a + b` 报错"来考这个机制。

### 难点 3：`^` 异或的真值表

异或是"相同为 false、不同为 true"，与直觉的"或"相反，容易记反。记法：异或异或，**有异才为真**。

### 易错点清单

- `++`、`--` 不能操作字面量（`5++` 报错）；
- 除法想得到小数，必须有小数参与运算，只改接收类型无效；
- `&`、`|` 不短路，右边一定会执行，含副作用的表达式要警惕；
- 三元运算符嵌套可读性差，超过两层建议改 if-else。
