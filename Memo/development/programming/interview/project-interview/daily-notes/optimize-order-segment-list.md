# 优化订单段列表

数据库中三个核心的索引概念：聚集索引、非聚集索引，以及和它们相关的回表查询、覆盖索引

### 一、聚集索引（Clustered Index）

#### 1. 核心定义

聚集索引**决定了数据在磁盘上的物理存储顺序**，它的索引结构和数据本身是“合二为一”的。可以把它想象成：

- 一本书的**目录**（索引）和**正文内容**（数据）是绑定的，目录的顺序就是正文页码的顺序（物理存储顺序）。
- 每张表**只能有一个**聚集索引（因为数据的物理存储顺序只能有一个）。

#### 2. 常见场景

- MySQL 的 InnoDB 引擎中，**主键索引默认就是聚集索引**。如果表没有显式定义主键，InnoDB 会自动选择一个唯一非空索引作为聚集索引；如果连这个都没有，会隐式创建一个自增的行ID作为聚集索引。
- 比如之前的 `orders_0` 表，如果有主键（如 `id`），那么 `id` 的索引就是聚集索引，表中数据会按照 `id` 的大小顺序物理存储。

### 二、非聚集索引（Non-Clustered Index）

#### 1. 核心定义

非聚集索引**不改变数据的物理存储顺序**，它的索引结构和数据是分开的。可以想象成：

- 一本书的**附录索引**（比如按关键词索引），附录里只记录关键词对应的页码，正文内容还是按原顺序存储，附录只是一个“指向”正文的指针。
- 每张表**可以有多个**非聚集索引（你之前创建的 `query_index_0` 就是非聚集索引）。

#### 2. 结构特点

非聚集索引的叶子节点存储的不是完整数据，而是：

- 如果表有聚集索引：存储**聚集索引的键值**（比如主键值）；
- 如果表没有聚集索引：存储**数据的物理地址**。

### 三、回表查询（Bookmark Lookup）

#### 1. 核心定义

通过**非聚集索引**查询数据，但需要的字段不在非聚集索引中时，数据库需要先通过非聚集索引找到聚集索引的键值，再通过聚集索引去查找完整数据，这个“二次查找”的过程就是回表查询。

#### 2. 例子

假设 `orders_0` 表的聚集索引是 `id`（主键），你创建的非聚集索引 `query_index_0` 包含 `orders_status、user_id、display、sort_by`：

```SQL
-- 需要回表的查询：非聚集索引只包含前4个字段，name不在其中
SELECT id, orders_status, user_id, name FROM orders_0 WHERE orders_status = 1;
```

执行过程：

1. 通过 `query_index_0`（非聚集索引）找到符合 `orders_status=1` 的记录的 `id`（聚集索引键）；
2. 再通过 `id`（聚集索引）去查找 `name` 字段——这一步就是回表。

### 四、覆盖索引（Covering Index）

#### 1. 核心定义

覆盖索引是一种**特殊的非聚集索引**：索引中包含了查询需要的**所有字段**，不需要回表就能完成查询，相当于“索引覆盖了查询需求”。

#### 2. 例子

还是上面的表，调整查询语句：

```SQL
-- 覆盖索引查询：需要的字段都在query_index_0中，无需回表
SELECT orders_status, user_id, display, sort_by FROM orders_0 WHERE orders_status = 1;
```

执行过程：

- 直接从 `query_index_0` 非聚集索引中获取所有需要的字段，不需要访问聚集索引，避免了回表，查询效率大幅提升。

#### 3. 实际应用

创建的 `query_index_0` 包含 `orders_status、user_id、display、sort_by`，如果你的业务查询只需要这四个字段，那么这个索引就是覆盖索引；如果还需要其他字段（比如 `order_time、amount`），建议把这些字段也加到索引中（作为**包含列**），比如：

```SQL
-- 扩展为覆盖索引（MySQL 8.0+支持INCLUDE，低版本可直接加在索引列后）
CREATE INDEX query_index_0
ON `jzo2o-orders-0`.orders_0 (orders_status asc, user_id asc, display asc, sort_by desc)
INCLUDE (order_time, amount); -- 包含查询常用但不用于筛选的字段
```

### 总结

1. **聚集索引**：决定数据物理存储顺序，一张表仅一个，InnoDB 中主键默认是聚集索引；
2. **非聚集索引**：不影响数据物理顺序，可创建多个，叶子节点存聚集索引键/物理地址；
3. **回表查询**：非聚集索引查不到全部字段时，需通过聚集索引二次查数据，会增加IO开销；
4. **覆盖索引**：非聚集索引包含查询所需所有字段，避免回表，是提升查询性能的关键优化手段。

之前创建的 `query_index_0` 的使用效率，设计索引时尽量让常用查询能命中覆盖索引，减少回表，能大幅提升分库分表场景下的查询性能。
