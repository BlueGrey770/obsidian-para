# 百居易专有名词

为统一业务口径，避免歧义，特制定本项目专有业务名词表。

| 名词 | 英文 | 定义 | 说明 |
|-|-|-|-|
| **房源** | Property | 民宿/酒店的整体资源单位。 | 房源是系统中的顶级资源，包含一个或多个房型。 |
| **房型** | Room Type | 房源下的分类，如大床房、双床房。 | 房型定义了房间的基本类型和规格。 |
| **房间** | Room | 实际可入住的具体房间。 | 每个房间都属于一个特定的房型。 |
| **库存** | Inventory | 某房间在某日期的可售数量。 | 库存是防止超售的关键，通过日期维度进行管控。 |
| **日历价** | Pricing | 按日期维度配置的动态价格。 | 支持平日、周末、节假日等差异化定价策略。 |
| **订单** | Order | 用户完成预订后生成的交易记录。 | 订单是交易的起点，后续会进入履约流程。 |
| **入住单** | Stay Order | 订单在履约阶段的具体执行实体。 | 从订单确认到退房完成的全流程记录。 |
| **房态** | Room Status | 房间当前状态（可售/在住/待清洁等）。 | 房态直接反映房间的可售与使用情况。 |
| **履约** | Fulfillment | 从下单到退房的完整执行过程。 | 涵盖入住前提醒、入住办理、在住管理、退房收尾等全流程。 |
| **账单明细** | Bill Detail | 最细粒度的收入/成本记录。 | 记录每一笔订单的收入、费用、退款等明细。 |
| **报表** | Statement | 按日期/房间/渠道聚合后的财务数据。 | 提供经营分析的关键指标，如入住率、RevPAR等。 |
| **HostGPT** | HostGPT | 基于大模型的智能客服消息助手模块。 | 集成在消息中心，用于自动回复房客咨询。 |
| **渠道映射** | Channel Mapping | 将房源与外部OTA平台进行关联的配置。 | 确保房源信息能同步到各销售渠道。 |
| **房态同步** | Room Status Sync | 系统与OTA平台之间房态信息的双向更新。 | 保证各渠道房态一致，避免超售。 |
| **微店小程序** | Mini Program Store | 房东的私域成交入口，支持房源展示、在线预订。 | 作为独立交易入口，订单会同步至PMS系统进行履约。 |
| **房态日历** | Room Status Calendar | 以日历形式展示房间在各日期的可售状态。 | 是运营人员进行开关房、库存调整的核心界面。 |
| **订单同步** | Order Sync | 外部OTA平台的订单自动接入PMS系统的过程。 | 实现多渠道订单的集中管理。 |
| **入住指南** | Check-in Guide | 发送给房客的包含入住流程、注意事项等信息的文档。 | 提升房客入住体验，减少人工沟通成本。 |
| **保洁任务** | Cleaning Task | 退房后自动生成的房间清洁任务。 | 任务会派发给保洁人员，并跟踪状态。 |
| **RevPAR** | Revenue Per Available Room | 每间可供出租客房的收入。 | 核心经营指标，计算公式为：平均房价 × 入住率。 |
| **多租户隔离** | Multi-tenant Isolation | 系统确保不同房东（租户）的数据、配置和业务流程完全独立。 | 这是SaaS系统的基础，通过租户ID进行严格隔离。 |
| **运营工作台** | Operations Workbench | 房东和运营人员进行房源维护、订单处理、消息回复等操作的统一界面。 | 是系统的核心操作入口。 |
| **RAG** | Retrieval-Augmented Generation | 检索增强生成技术，用于提升AI回答的准确性。 | 在HostGPT中，通过检索租户知识库来增强回答的专业性。 |
| **Function Calling** | Function Calling | AI模型调用外部工具或API获取实时数据的能力。 | 使HostGPT能够查询实时订单、房态等业务数据。 |
| **消息聚合** | Message Aggregation | 将来自不同渠道（如OTA、小程序）的房客消息汇总到统一的消息中心。 | 便于运营人员集中处理所有客情咨询。 |
| **自动化规则** | Automation Rule | 系统根据预设条件自动触发后续动作的配置。 | 例如，在退房后自动触发保洁任务。 |
| **入住节点** | Check-in Node | 入住流程中的关键时间点或操作步骤。 | 如入住前提醒、入住确认、退房前提醒等。 |
| **任务状态流转** | Task Status Flow | 任务从创建、派发、执行到完成的状态变化过程。 | 用于跟踪任务的全生命周期。 |
| **经营统计** | Business Statistics | 对订单、收入、入住率等数据进行汇总和分析。 | 为房东提供经营决策依据。 |
| **账单明细归一** | Bill Detail Normalization | 将不同渠道、不同格式的订单数据，按照统一口径进行整理和记录。 | 是生成准确财务报表的前提。 |
| **RAG知识库** | RAG Knowledge Base | 用于HostGPT进行检索的、包含房源规则、入住指南等信息的向量数据库。 | 基于Elasticsearch实现，是AI准确回答的基础。 |
| **幂等控制** | Idempotency Control | 确保重复的请求不会导致业务状态的异常变化。 | 在订单创建、库存占用等场景中至关重要。 |
| **异步补偿** | Asynchronous Compensation | 当主流程出现异常时，通过异步任务进行后续的修正或重试。 | 保障系统在高并发下的数据一致性。 |
| **分布式锁** | Distributed Lock | 在分布式系统中，用于控制共享资源并发访问的机制。 | 在库存服务中，用于解决并发库存占用问题。 |
| **事件驱动** | Event-driven | 系统通过发布和订阅事件来解耦服务间的通信。 | 例如，订单状态变更会触发入住服务的相应动作。 |
